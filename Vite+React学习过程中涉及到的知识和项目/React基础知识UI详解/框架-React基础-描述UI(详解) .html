构建组件：

  • 第一步导出组件
    • export default前缀时JS的语法，用于默认导出文件中的一个主要函数
  • 第二步定义函数
    • 使用function Name（）{}，定义名为Name的JS函数。
    • React组件就是常规的JS函数，但是组件的名称必须以大写字母开头
  • 第三步添加标签
    • 组件会返回一个类似HTML标签的语法，实际上是JS，这种语法成为JSX，允许在JS中嵌入标签
    • 返回的语句可以全写在一行上，如果标签和return不在同一行需要括号包裹

使用JSX书写标签语言：

JSX是JS的扩展语法，可以在JS文件中书写类似于HTML的标签

JSX：将标签引入JS

  • 网页构建在HTML、CSS、JS基础上，习惯于网页内容放在HTML，样式放在CSS中，逻辑放在JS中
  • 在React中，逻辑渲染和标签可以共同存放在组件中
  • 每个React组件都是一个JS函数，它会返回HTML标签，React会直接将这个标签渲染到浏览器中。React组件使用JSX语法扩展来描述标签，JSX类似于HTML，但是JSX语法更为严格、动态

将HTML转化为JSX

  • 现有的完全有效的HTML标签，直接迁移到JS组件中，并不能正常工作，甚至会报错，因为JSX语法更为严格，有更多的限制规则。

JSX规则：

  • 只能返回一个根元素
  • 【空标签被称为Fragment，React Fragment允许将子元素分组，而不是在HTML中添加额外的结构】
    • 如果要在组件中包含多个元素，需要使用父标签将其包裹起来
      使用div或者空的标签<></>

      <>

      <h1>海蒂·拉玛的待办事项</h1>

      <img src="https://i.imgur.com/yXOvdOSs.jpg" alt="Hedy Lamarr" class="photo">

      <ul>

      ...

      </ul>

      </>

  • 标签必须闭合
    • JSX要求标签必须正确闭合，自闭合标签必须书写为<img />
  • 大部分属性使用驼峰式命名法
    • JSX最终会被转化为JS，而JSX中的属性也会变成JS对象中的键值对。
    • 组件中常用变量的方式来读取属性值，但是JS对变量的命名有限制
    • React中大部分HTML和SVG属性使用驼峰式命名法表示，DOM属性命名亦是如此
  • 提示：使用JSX转化器
    • 将现有的HTML中的所有属性转化为JSX格式是繁琐的，建议使用转化器将HTML和SVG标签转化为JSX

JSX允许在JS中编写类似HTML的标签，从而使渲染的逻辑和内容可以编写在一起，在JSX中使用大括号可以在标签中添加JS逻辑或者引用动态的属性。类似于格式化引用变量

摘要：将参数与函数分离

  • 要传递 props，请将它们添加到 JSX，就像使用 HTML 属性一样。
  • 要读取 props，请使用 function Avatar({ person, size }) 解构语法。
  • 你可以指定一个默认值，如 size = 100，用于缺少值或值为 undefined 的 props 。
  • 你可以使用 <Avatar {...props} /> JSX 展开语法转发所有 props，但不要过度使用它！
  • 像 <Card><Avatar /></Card> 这样的嵌套 JSX，将被视为 Card 组件的 children prop。
  • Props 是只读的时间快照：每次渲染都会收到新版本的 props。
  • 你不能改变 props。当你需要交互性时，你可以设置 state。

选择性的包含JSX：

  • 在之前的例子中，在组件内部空值JSX树会返回一些东西，在渲染中总会有一些重复的内容
    <li className=“item”>{name}√</li>

    类似于

    <li className=”item”>{name}</li>
  • 两个条件分支都会返回<li>
    if (isPacked) {
    return <li className="item">{name} ✅</li>;
    }
    return <li className="item">{name}</li>;
  • 重复的内容不会报错，但是繁杂了以后会导致代码难以维护，可以选择性的包含一小段JSX来让代码更加简洁

使用key来保持列表项的顺序：

  • 上面对列表进行操作的代码，都会报错

    Warning: Each child in a list should have a unique “key” prop.
  • 因为必须给数组中的每一项都指定一个key—可以是字符串或者数字的形式，只要能唯一标示出各个数组项即可<li key={person.id}>...</li>
  • 这个key会告诉React，每个组件对应着数组中哪一项，React可以把他们匹配起来，这个对于数组项的排序、插入、删除等操作很有用
  • key的值应该在数据中准备好

如何设定key值

不同来源的数据对那个这不同的key的获取方式

  • 来自数据库的数据：可以直接使用数据表中的主键，主键具有唯一性和
  • 本地产生数据：可以使用一个自增的计数器，或者一个类似uuid的库来生成key

key需要满足的条件

  • key值在兄弟节点之间是唯一的，不要求全局唯一，在不同的数组中可以使用相同的key
  • key值不可改变，不要再渲染时动态的生成key

React中为什么需要key：

React中需要key和文件夹里的文件需要命名道理类似，key可以从众多兄弟元素中唯一标识出某一项JSX节点，进而一个仔细选择的key能提供的信息要比元素在数组中的索引重要许多。即使元素的位置在渲染过程中发生了改变，记录的key值也能让React在整个生命周期中一直能够识别他

直接把数组项的索引当作 key 值来用，实际上，如果你没有显式地指定 key 值，React 确实默认会这么做。但是数组项的顺序在插入、删除或者重新排序等操作中会发生改变，此时把索引顺序用作 key 值会产生一些微妙且令人困惑的 bug
与之类似，请不要在运行过程中动态地产生 key，像是
key={Math.random()} 这种方式
有一点需要注意，组件不会把
key 当作 props 的一部分。Key 的存在只对 React 本身起到提示作用。如果你的组件需要一个 ID，那么请把它作为一个单独的 prop 传给组件： <Profile key={id} userId={id} />。

保持组件单一纯粹：

部分JS函数是单一的纯粹的，这类函数被称为纯函数。纯函数仅执行计算操作，可以通过将组件按照纯函数编写，来避免代码库过长出现不可预测的bug

纯函数：组件作为公式

纯函数具有如下特征：

  • 只负责自己的任务：不会更改在函数调用前就已经存在的对象和变量
  • 输入相同，输出相同：给定相同的输入，纯函数返回相同的结果

React围绕纯函数概念设计。假设编写的组件是纯函数，输入相同的内容，组件总是返回相同的JSX

function Recipe({ drinkers }) {
return (
<ol>
<li>Boil {drinkers} cups of water.</li>
<li>Add {drinkers} spoons of tea and {0.5 * drinkers} spoons of spice.</li>
<li>Add {0.5 * drinkers} cups of milk to boil and sugar to taste.</li>
</ol>
);
}

export default function App() {
return (
<section>
<h1>Spiced Chai Recipe</h1>
<h2>For two</h2>
<Recipe drinkers={2} />
<h2>For a gathering</h2>
<Recipe drinkers={4} />
</section>
);
}
  • 给函数Recipe传入drinkers={2}，将返回包含两杯水的JSX，永远如此，就像数学公式一般。

副作用：不符合预期的结果：

React的渲染过程必须是单一纯粹的，组件应该只返回他们的JSX，不改变存在的任何变量核对下。

错误示例，修改了渲染前就存在的变量。
let guest = 0;

function Cup() {
// Bad：正在更改预先存在的变量！
guest = guest + 1;
return <h2>Tea cup for guest #{guest}</h2>;
}

export default function TeaSet() {
return (
<>
<Cup />
<Cup />
<Cup />
</>
);
}
  • Cup组件在读取外部变量guest时候，会多次调用这个组件，生成不同的JSX，如果其他组件读取guest也会产生不同的JSX
  • 可以将guest作为prop传入来修复此组件
function Cup({ guest }) {
return <h2>Tea cup for guest #{guest}</h2>;
}

export default function TeaSet() {
return (
<>
<Cup guest={1} />
<Cup guest={2} />
<Cup guest={3} />
</>
);
}
  • 现在的组件就是单一纯粹的，返回的JSX只依赖于guest

局部mutation：组建的特殊用法：

  • 上述示例的渲染过程，组件改变了渲染前存在的变量，这种行为称为突变。纯函数不会改变函数作用域外的变量、对象
  • 可以在渲染时更改刚刚创建的变量和对象，下例创建数组，将其分配给一个cups变量，
    function Cup({ guest }) {
    return <h2>Tea cup for guest #{guest}</h2>;
    }

    export default function TeaGathering() {
    let cups = [];
    for (let i = 1; i <= 12; i++) {
    cups.push(<Cup key={i} guest={i} />);
    }
    return cups;
    }
    • 如果cups数组在函数之外创建，这就会出现问题。push方法就会更改预先存在的对象。这里不会，在每次渲染时都会重新在函数内部创建一次，这里就是局部变量的作用

常出现副作用场景：

  • 函数式编程很大程度上依赖于纯函数，在某些情况下纯函数又不得不发生改变。包括更新屏幕、启动动画、更写数据等，这些行为被称为副作用。这些事额外发生的改动，与渲染过程无关
  • 在React中，副作用属于事件处理程序。就是在进行操作时运行的函数，即使事件处理程序是在组件内部定义的，他们也不会在渲染期间运行（类似于按钮触发事件），因此事件处理程序无需是纯函数
  • 最后万不得已，如果无法为副作用找到合适的事件处理程序，可以调用组件中的useEffect方法将其附加到返回的JSX中，这会在React渲染结束后执行

将UI视为树：

当React应用逐渐成型时，许多组件会出现嵌套

React为解决该问题，将UI建模为树，将应用程序理解为树对于理解组件之间的关系以及调试性能和状态管理等未来将会遇到的一些概念有用

将UI视为树：

  • 树是项目和UI之间的关系模型，通常使用树结构来表示UI，例如浏览器使用树结构来构建HTML（DOM）和CSS（CSSOM），移动平台也是用树来表示其视图层次机构
    • React从组件中创建UI树，UI树最后用于渲染DOM
  • 与浏览器和移动平台一样，React使用树结构来管理和建模React应用程序中组件之间的关系。树用于理解数据如何在React应用程序中流动以及如何优化呈现和应用程序大小

渲染树：

  • 组件的一个主要特征就是能够由其他组件组合而成，组件之间嵌套，由父组件和子组件概念
  • 在渲染React应用时，可以在渲染树中建模这种关系
    • 渲染树示例
      import FancyText from './FancyText';
      import InspirationGenerator from './InspirationGenerator';
      import Copyright from './Copyright';

      export default function App() {
      return (
      <>
      <FancyText title text="Get Inspired App" />
      <InspirationGenerator>
      <Copyright year={2004} />
      </InspirationGenerator>
      </>
      );
      }
    • 渲染树结构如下
    • 树由节点组成，一个节点为一个组件，如App、FancyText、Copyright等
    • React渲染树中，根节点是应用程序的根组件，React渲染的第一个组件，书中的每个箭头都是父组件指向子组件
  • 渲染树表示React应用程序的单个渲染过程，在条件渲染中，父组件可以根据传递不同数据而渲染不同的子组件

模块依赖树：

在React应用程序中，可以使用树来建模的原因是应用程序的模块依赖关系。当拆分组件和逻辑到不同的文件中，就创建了JS，在这些模块中可以到处组件、函数或常量

模块依赖树中的每个节点都是一个模块，每个分支代表该模块中的import语句

  • 根基构建一个模块依赖树
    • 树的根节点是跟模块，也是入口文件，通常包含根组件的模块。
    • 与渲染树相比，存在相似的结构，也有显著的差别
      • 构成依赖树的节点是模块，而不是组件
      • 非组件模块，如inspirations.js，在树中也有体现，在渲染树中仅为封装组件
      • Copyright.js在App.js下。在渲染树中Copyright作为组件出现，因为InspirationGenerator接受JSX作为childrenprops，将Copyright作为子组件渲染，但不导入该模块
  • 依赖书对于确定运行React应用程序的模块很有用，在生产环境下构建React应用程序，通常会有构建步骤
  • 构建步骤捆绑所有必要的JS来供客户端使用。负责该步骤的工具称为bundler捆绑器
  • bundler捆绑器，使用依赖树来确定应包含哪些模块。
  • 随着应用程序增长，捆绑包大小通常会增加，大型捆绑包大小对于哭护短来说，下载和运行成本高昂，并会延迟UI绘制的时间。
