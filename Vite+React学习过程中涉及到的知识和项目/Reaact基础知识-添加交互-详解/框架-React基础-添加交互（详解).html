框架-React基础-添加交互（详解）

响应事件：

使用React可以在JSX中添加事件处理函数，其中事件处理函数为自定义函数，会在响应交互时触发。如点击、悬停、表单输入框获得焦点。

添加事件处理函数：

  • 如需添加一个事件处理函数，需要先定义一个函数，然后将其作为prop传入合适的JSX标签中
    • 例如，一个未绑定事件的按钮
      export default function Button() {
      return (
      <button>
      未绑定任何事件
      </button>
      );
      }
    • 三个步骤，为按钮添加交互，在用户点击时显示消息
      • 在Button组件内部声明一个handleClick的函数
      • 实现函数内部的逻辑（使用alert来显示消息）
      • 添加onClick={handleClick}到button的JSX中
        export default function Button() {
        function handleClick() {
        alert('你点击了我！');
        }

        return (
        <button onClick={handleClick}>
        点我
        </button>
        );
        }

  • 可以自定义一个handleClick函数，将其作为prop传入<button>，其中hanldeClick时事件处理函数，有如下特点
    • 通常在组件内部定义
    • 名称以hancdle开头后面跟事件名称
  • 或者也可以在JSX中定义一个内联的事件处理函数
    <button onClick={function handleClick() {
    alert('你点击了我！');
    }}>
  • 或者，直接使用更为简洁的箭头函数
    <button onClick={() => {
    alert('你点击了我！');
    }}>

上述所有方式都是等效的，根据函数体复杂程度选择不同的处理方式

在事件处理函数中读取props：

  • 由于事件处理函数在组件内部声明，因此他们可以直接访问组件的props
    • 示例，按钮点击，弹出message的prop的alert
      function AlertButton({ message, children }) {
      return (
      <button onClick={() => alert(message)}>

      可以直接访问作为prop的message
      {children}
      </button>
      );
      }

      export default function Toolbar() {
      return (
      <div>
      <AlertButton message="正在播放！">
      播放电影
      </AlertButton>
      <AlertButton message="正在上传！">
      上传图片
      </AlertButton>
      </div>
      );
      }

事件传播：

  • 事件处理函数还将捕获来自子组件的事件，通常会称为事件沿着树向上传播，她是从事件发生开始的地方，然后沿着树向上传播。
    • 示例，div包含两个按钮，div和每个按钮都有自己的onClick处理函数
      export default function Toolbar() {
      return (
      <div className="Toolbar" onClick={() => {
      alert('你点击了 toolbar ！');
      }}>
      <button onClick={() => alert('正在播放！')}>
      播放电影
      </button>
      <button onClick={() => alert('正在上传！')}>
      上传图片
      </button>
      </div>
      );
      }
    • 点击任意按钮，自身的onClick会首先执行，然后父级的div的onClick会接着执行，出现两条信息，如果点击div本身，就只有父级的toolbar的onClick会执行

阻止传播：

  • 事件处理函数接收一个事件对象作为唯一的参数，按照惯例它通常被称为e，代表event事件，可以使用此对象来读取有关事件的信息。
    • 这个事件对象允许阻止传播，如果想要阻止一个事件到达父组件，如下实例，Button组件调用e.stopPropagation（）；
    function Button({ onClick, children }) {
    return (
    <button onClick={e => {
    button自身限制上传事件
    e.stopPropagation();
    onClick();
    button prop函数
    }}>
    {children}
    </button>
    );
    }

    export default function Toolbar() {
    return (
    <div className="Toolbar" onClick={() => {
    alert('你点击了 toolbar ！');
    }}>
    <Button onClick={() => alert('正在播放！')}>
    播放电影
    </Button>
    <Button onClick={() => alert('正在上传！')}>
    上传图片
    </Button>
    </div>
    );
    }
    • 点击按钮，发生事件
      • React调用了传递给button的onClick处理函数
      • 定义在Button中的处理函数执行如下操作
        • 调用e.stopPropagation（）阻止事件上传
        • 调用onClick函数，他是从Toolbar组件传递的prop
      • 在Toolbar组件中定义的函数，显示按钮对应的alert
      • 上传被组织1，父级div的onClick处理函数不会执行。

捕获阶段事件：

  • 少数情况下，需要捕获子元素上的所有事件，即便他组织了传播，
  • 例如你可能相对每次点击进行埋点记录，可以通过在事件名称末尾添加Capture来实现
    <div onClickCapture={() => { /* 这会首先执行 */ }}>
    <button onClick={e => e.stopPropagation()} />
    <button onClick={e => e.stopPropagation()} />
    </div>
  • 事件分三个阶段传播
    • 首先向下传播，调用所有的onClickCapture处理函数
    • 执行被点击的元素的onClick处理函数
    • 向上传播，调用所有的onClick处理函数
  • 捕获事件对于路由或者数据分析之类的代码很有效

传递处理函数作为事件传播的替代方案

  • 示例，此处的点击事件处理函数限制性了一行代码，然后调用父组件传递的onClick prop
    function Button({ onClick, children }) {
    return (
    <button onClick={e => {
    e.stopPropagation();
    onClick();
    }}>
    {children}
    </button>
    );
    }
  • 可以再调用父元素onClick函数之前，像这个处理函数添加更多代码，这个模式是事件传播的另一种代替方案。
  • 让子组件处理事件，父组件指定一些额外的行为，
  • 与事件传播不同，这个并非自动，使用这种模式可以清楚的追踪某个事件触发执行的整条代码链。

阻止默认行为

  • 某些浏览器时间具有与事件相关连的默认行为，例如点击form表单内部的按钮，会出发表单提交事件，默认情况下会重新加载整个页面。
    export default function Signup() {
    return (
    <form onSubmit={() => alert('提交表单！')}>
    <input />
    <button>发送</button>
    </form>
    );
    }
  • 可以调用事件对象的e.preventDefault（）来阻止这种情况发生。
    export default function Signup() {
    return (
    <form onSubmit={e => {
    e.preventDefault();
    alert('提交表单！');
    }}>
    <input />
    <button>发送</button>
    </form>
    );
    }

事件处理函数可以包含副作用：

是按处理函数是执行副作用的最佳位置。

  • 与渲染函数不同，事件处理函数不需要纯函数，因此它可以用来更改某些值的位置。例如更改输入框的值以响应键入，或者更改列表来响应按钮的处罚，但是为了更改某些信息，需要使用state存储

组件的记忆：state

组件通常需要根据交互来更改屏幕上显示的内容。例如，输入表单应该更新输入字段，单击轮播图上的“下一个”来更改显示的图片，单击“购买”应该将商品放入购物车。组件需要“记忆”某些东西，比如当前的输入值、当前图片、购物车。

在React中这种组件特有的记忆被称为state

React中第一个Hook-useState

  • 在React中，useState以及任何其他以use开头的函数被称为Hook
  • Hook是特殊的函数，旨在React渲染时有效。可以使用不同的React特性
  • State只是这些特征中的一个

剖析useState：

  • 当你调用useState时，要告诉React这个组件记住一些东西
    • const 【index，setIndex】=useState（0）；
  • 如上例而言。useState的唯一参数是state变量的初始值。index的初始值被useState（0）设置为0
  • 每次渲染时，useState都会给你一个包含两个值的数组。
    • state变量（index）会保存上次渲染的值
    • state setter函数（setIndex）可以更新state变量并触发React重新渲染组件。
  • const【index，setIndex】=useState（0）；实际发生
    • 组件进行第一次渲染。将0作为index初始值传递给useState，它将返回【0，setIndex】，React记住0为最新的state值
    • 你更新了state，当用户点击按钮时，会调用setIndex（index + 1）。index是0，所以为setIndex（1），这告诉React现在记住index为1并处罚下一次渲染
    • 组件进行第二次渲染，React仍然看到useState（0），但是因为React记住了你将index设置了1，它将返回【1，setIndex】。
    • 以此类推

赋予一个组件多个state变量：

  • 你可以在一个组件中拥有任意多种类型的state。该组件由两个state变量，一个为数字index，和一个布尔值showMore，点击show details会改变showMore的值
    import { useState } from 'react';
    import { sculptureList } from './data.js';

    export default function Gallery() {
    const [index, setIndex] = useState(0);
    const [showMore, setShowMore] = useState(false);

    function handleNextClick() {
    setIndex(index + 1);
    }

    function handleMoreClick() {
    setShowMore(!showMore);
    }

    let sculpture = sculptureList[index];
    return (
    <>
    <button onClick={handleNextClick}>
    Next
    </button>
    <h2>
    <i>{sculpture.name} </i>
    by {sculpture.artist}
    </h2>
    <h3>
    ({index + 1} of {sculptureList.length})
    </h3>
    <button onClick={handleMoreClick}>
    {showMore ? 'Hide' : 'Show'} details
    </button>
    {showMore && <p>{sculpture.description}</p>}
    <img
    src={sculpture.url}
    alt={sculpture.alt}
    />
    </>
    );
    }
  • 如果不相关，存在state变量是一个好主意，例如本例中index和showMore，但是，如果发现经常同时更改两个state变量，那么将二者合并更好。
  • 例如，如果你有一个包含多个字段的表单，那么由一个值为对象的state变量比每个字段对应一个state变量更方便

State是隔离且私有的：

  • State是屏幕上组件实例内部的状态，“如果渲染同一个组件两次，每个副本都会有完全隔离的state”改变其中一个不会改变另一个

  • state与声明在模块顶部的铍铜变量不同的原因。
    • State不依赖于特定的函数调用或者在代码中的位置，它的作用域只限于屏幕上的模块特定区域，渲染了两个<Gallery />组件，所以他们的state是分别存储的。

渲染和提交

  • 组件显示到屏幕之前，必须被React渲染。步骤如下：
  • 步骤1：触发一次渲染-两种原因导致组件渲染
    • 组件的初次渲染
      • 当应用启动时，会触发初次渲染。框架和沙箱有时会隐藏这部分代码，但是通过调用createRoot的方法并传入目标DOM节点，然后用你的组件调用render函数完成。
        import Image from './Image.js';
        import { createRoot } from 'react-dom/client';
        试着注释掉root.render（），组件会消失
        const root = createRoot(document.getElementById('root'))
        root.render(<Image />);
    • 状态更新时重新渲染
      • 一旦组件被初次渲染，就可以使用set函数更新状态来触发之后的渲染。更新组件的状态会自动讲一次渲染送入对列。
  • 步骤2：React渲染你的组件
    • 在触发渲染后，React回调用你的组件来确定要在屏幕上显示的内容。渲染中既是React再调用你的组件
      • 在初次渲染时，React会调用根组件
      • 对于后续的渲染，React会调用内部状态更新触发渲染的函数组件。
    • 这个过程是递归的：如果更新后的组件会返回某个另外的组件，那么React会渲染这个返回的组件，如果这个组件又返回了某个组件，React有会渲染那儿组件，以此类推，这个过程会持续，直到没有嵌套组件并且React确切知道那些东西应该被显示到屏幕上
      • 下例，React会调用Gallery（）和Image（）若干次
        export default function Gallery() {
        return (
        <section>
        <h1>鼓舞人心的雕塑</h1>
        <Image />
        <Image />
        <Image />
        </section>
        );
        }

        function Image() {
        return (
        <img
        src="https://i.imgur.com/ZF6s192.jpg"
        alt="'Floralis Genérica' by Eduardo Catalano: a gigantic metallic flower sculpture with reflective petals"
        />
        );
        }
        import Gallery from './Gallery.js';
        import { createRoot } from 'react-dom/client';

        const root = createRoot(document.getElementById('root'))
        root.render(<Gallery />);
        • 在初次渲染中，React为<section><h1><img>三个标签创建DOM节点
        • 在一次重渲染过程中，React将计算它们的属性，自上次渲染后有何更改，在下一步阶段提交之前，不会对这些信息进行操作
  • 步骤3：React把更改提交到DOM上
    • 在渲染调用组件之后，React会修改DOM
      • 对于初次渲染，React会使用appendChild（）DOMAPI将其创建的所有DOM节点放在屏幕上
      • 对于重渲染，React将应用最少的必要操作（渲染时计算），这是DOM与最新的渲染输出相互匹配。
    • React尽在渲染之间存在差异是才会更改DOM节点
      • 例如，一个组件，每秒使用从父组件组件传递下来的不同属性重新渲染一次。添加一些文本到<input>标签，更新他的value，但是文本不会再组件重渲染时消失

        return (
        <>
        <h1>{time}</h1>
        <input />
        </>
        );
        }
        • 这个例子会正常运行，因为React在最后会使用最新的time更新h1标签的内容，他看到<input>标签出现在JSX中与上次相同的位置，因此React不会修改<input>标签或者他的value。

结尾：浏览器绘制：

  • 在渲染完成并且React更新DOM之后，浏览器会重新绘制屏幕。尽管这个过程被称为‘浏览器渲染’，我们将其称为‘绘制’，以避免在这些文档的其余部分中出现混淆。

渲染时会及时生成一个快照，记录当前的状态：

  • ‘正在渲染’意味着React正在调用组件，从该函数返回的JSX像是某个时间点上UI的快照，它的props、事件处理函数和内部变量都是根据当前渲染时的state被计算出来。
  • 返回的UI快照是可以交互的，其中包括类似事件处理函数的逻辑，这些逻辑指定如何对输入做出响应，React会更新屏幕来匹配这张快照，并绑定事件处理函数，
  • 按下按钮会触发你JSX中的点击事件处理函数
    • 当React重新渲染一个组件时，会发生一下步骤
      • Reaact会再次调用组件函数
      • 函数会返回新的JSX快照
      • React会更新界面来匹配返回的快照
  • 作为一个组件的state状态记忆，state不同于在函数返回之后就小时的普通变量，state实际存储与函数之外某个特定地点。
  • 当React调用你的组件时，他会为特定的那一次渲染提供一张state快照，组件会在JSX中返回一张包含一整套新的props和事件处理函数的UI快照，其中所有的值都是根据那一次渲染中state的值被计算出来
    • 例子展示原理：点击+3按钮会调用setNumber（number + 1）三次，从而使计数器递增三次

      • 就好比在点击按钮时，此时的number为0，记录一张快照
      • 这个组件在运行的所有函数，都是基于这张快照，number=0
      • 在第一个+1函数过后，number的值变为1
      • 第二个+1函数的number也是0，结果也为1
    • 设置state只会为下一次渲染变更state的值

随时间变化的state：

  • 用上述的理论解释下例

      alert(0);

  • 一个state变量的值永远不会在一次渲染的内部发生变化，即使事件处理函数的代码是异步的。
  • React会使state的值始终固定在一次渲染的各个事件处理函数内部。无需担心代码运行时state是否发生变化

把一系列state更新加入队列：

设置组件state会把一次重新渲染加入对列，但是有事希望下次渲染加入队列之前，对state的值进行多次操作。

React会对state更新进行批处理

  • 上述的+3示例，每一次渲染的state值都是固定的，无论调用多少次+1，在第一次渲染的组件内部number总是0
  • React会等到事件处理函数中的所有代码都运行完毕之后在处理你的state更新。这就是重新渲染为什么只发生在所有的setNumber（）调用之后
    • 类似于餐厅点菜的服务员，不会再你说完第一道菜就跑去厨房，相反会让你点完所有菜，你修改菜品，设置会帮桌上其他客人点菜
    • 这就可以设置多个state变量，设置来自不同组件的state变量，而不会触发太多的重新渲染
    • 也意味着只有在你的事件处理函数以及其中的所有代码执行完后，UI才会更新。这种特性就是批量处理
  • 批量处理会使你的React应用运行更快，会避免处理只更新一部分的state变量的半成品渲染
  • React不会跨越多个需要可以触发的事件（如点击）在进行批量处理，每次点击都是单独处理。

更新state中的对象

state中可以保存任意类型的JS值，包括对象、数组等。但是不可以直接修改存放在React state中的对象，相反，如果更新一个对象时，需要创建一个新的对象，或者拷贝一个副本，然后将state更新为此对象

mutation（突变）：

  • 可以在state中存放任意类型的JS值
    • const【x，setX】=useState（0）；
  • 目前为止，尝试过在state中存放数字、字符串、布尔值，这些类型的值在JS中是不可变的immutable。这意味着他们不能被改变或是只读的，可以替换他们的值，来触发重新渲染
    • setX（5）
  • state x从0被覆盖为5，但是数字0本身并没有改变，在JS中，无法对内置的原始值，数字、字符串、布尔值进行任何改变
  • 如果在state中存放对象数据类型
    • const【position，setPosition】=useState（{x：0，y：0}）；
  • 从技术上讲，可以改变对象自身的内容，如果改变之后，就制造了一个mutation（突变）
    • position.x=5；
  • 然而严格来说React state中存放的对象是可变的，但你应该像处理数字、布尔值、字符串一样视为不可变。因此应该替换他们的之，而不是对他们进行修改

为什么在React中不推荐直接修改state：

  • 调试：如果使用console.log并且不直接修改state，你之前日志中的state值就不会被新的state变化所影响，你就可以清楚的看到两次渲染之间的state的值是什么变化。
  • 优化：React常见的优化策略，依赖于如果之前的props或者state的值和下一次相同就跳过渲染，如果你从未直接修改state，那么就可以看到state是否发生了变化，如果prevObj===obj，那么你就可以肯定这个对象内部并没有发生变化
  • 新功能：正构建的React新功能依赖于state被像快照一样看待。如果直接修改state的历史版本，可能会影响你使用这些新功能
  • 需求变更：有些功能在不出现任何修改的情况下会更容易实现，比如实现撤销/恢复、展示修改历史，或是允许用户把表单重置成某个之前的值，这是因为可以把state之前的拷贝保存到内存中，那么后面要实现这样的功能就会变得很困难。
  • 更简单的实现：React并不依赖于mutation，所以你不需要对对象进行任何的特殊操作，它不需要像很多‘响应式’的解决方案一样去劫持对象的属性。总是使用代理把对象包裹起来，或者在初始化时做其他工作，这也是Reacy允许你把任何对象存放在state中。不会造成有任何额外的性能或者正确性问题的原因。

更新state中的数组：

数组是另一种可以存储在state中的JS对象，他虽然是可变的，但是却应该视为不可变，同对象一样，当你想要更新存储与state中的数组时，你需要创建一个新的数组（或者创建一份已有数组的拷贝），并使用新数组设置state

在没有mutation的前提下更新数组：

  • 在JS中数组是另一种对象，同对象一样，你需要React state中的数组视为只读。这意味着不应该使用类似于【arr【0】=‘bird’】这样的方式来重新分配数组中的元素，也不应该使用会直接修改原数组的方法，例如push（）或者pop（）
  • 相反每次要更新一个数组时，你需要把一个新的数组传入state的setting方法中，为此你可以通过使用filter（）和map（）这样不会直接修改原始值的方法，从原始数组生成新的数组，然后就可以将state设置为这个新生成的数组
  • 下面是常见数组操作的参考表，当你操作React state中的数组时，使用右列方法，或者使用immer就可以使用所有方法

向数组中添加元素：

  • 使用push（）会修改原始数组，使用按钮并不会重新渲染

  • 相反你应该创建一个先数组，其中包含可原始数组的所有元素以及一个在末尾的新元素，这可以通过很多方法实现，最常见的就是…数组展开语法

替换数组中的元素：

  • 替换数组中的一个或多个元素是常见的，类似arr【0】=‘bird’这样的赋值语句会直接修改数组，所以应该使用map。
  • 要替换一个元素，请使用map创建一个新数组，在map回调中，第二个参数是元素的索引。使用索引来判断最终是返回原始的元素，还是替换成其他的值
    import { useState } from 'react';

    let initialCounters = [
    0, 0, 0
    ];

    export default function CounterList() {
    const [counters, setCounters] = useState(
    initialCounters
    );

    function handleIncrementClick(index) {
    const nextCounters = counters.map((c, i) => {
    if (i === index) {
    // 递增被点击的计数器数值
    return c + 1;
    } else {
    // 其余部分不发生变化
    return c;
    }
    });
    setCounters(nextCounters);
    }

    return (
    <ul>
    {counters.map((counter, i) => (
    <li key={i}>
    {counter}
    <button onClick={() => {
    handleIncrementClick(i);
    }}>+1</button>
    </li>
    ))}
    </ul>
    );
    }
    • c: 在每一次迭代中，c 会被赋值为 counters 数组中当前正在被处理的元素的值。例如，在第一次迭代中，c 是 0（initialCounters 的第一个元素）；在第二次迭代中，c 是 0（initialCounters 的第二个元素），以此类推。
    • i: 在每一次迭代中，i 会被赋值为 counters 数组中当前正在被处理的元素的索引（位置）。例如，在第一次迭代中，i 是 0；在第二次迭代中，i 是 1，以此类推。

向数组中插入元素：

  • 有时会像数组特定位置插入一个元素，这个位置不在数组头尾。可以将数组展开运算符…和slice（）方法一起使用。slice方法让你从数组中切除一篇，为了将元素插入数组，你需要展开原数组在插入点之前的切片，然后插入新元素，最后展开原数组中剩下的部分
  • 示例，插入按钮会将元素插入到数组中索引为1的位置
    import { useState } from 'react';

    let nextId = 3;
    const initialArtists = [
    { id: 0, name: 'Marta Colvin Andrade' },
    { id: 1, name: 'Lamidi Olonade Fakeye'},
    { id: 2, name: 'Louise Nevelson'},
    ];

    const [artists, setArtists] = useState(
    initialArtists

    const insertAt = 1; // 可能是任何索引
    const nextArtists = [
    // 插入点之前的元素：
    ...artists.slice(0, insertAt),
    // 新的元素：
    { id: nextId++, name: name },
    // 插入点之后的元素：
    ...artists.slice(insertAt)
    ];
    setArtists(nextArtists);
    setName('');
    }

    return (
    <>

    value={name}
    onChange={e => setName(e.target.value)}
    />

    插入
    </button>

    {artists.map(artist => (
    <li key={artist.id}>{artist.name}</li>
    ))}
    </ul>
    </>
    );
    }
    • input 中的 setName(e.target.value) 响应用户的输入，实时更新 name state。
    • handleClick 中的 setName('') 在添加完新的艺术家后，清空 name state，从而清空输入框。
