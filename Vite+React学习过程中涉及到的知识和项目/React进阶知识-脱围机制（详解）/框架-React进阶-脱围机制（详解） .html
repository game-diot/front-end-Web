使用ref引用值：

希望组件来记住某些信息，又不希望这些信息触发新的渲染，使用ref

给组件添加ref：

  • 通过从React中导入useRef Hook来为组件添加一个ref：
    • import {useRef} from ‘react’
  • 在组件中调用useRef Hook并传入想要引用的初始值为唯一参数，
    • 例如，这里的ref引用的值时0
      • const ref = useRef（0）；
    • useRef返回一个对象
      • { current: 0 // 你向 useRef 传入的值 }
  • 可以使用ref.current属性访问该ref的当前值，这个值是有意被设置为可变的。就意味着可以读取它也可以更改它。
    • 实例：每次点击按钮会使ref.current递增
      import { useRef } from 'react'; 引入Hook

      export default function Counter() {

      let ref = useRef(0); 定义ref初始值

      function handleClick() {

      ref.current = ref.current + 1; 调用函数会使ref值+1

      alert('你点击了 ' + ref.current + ' 次！'); 提示当前ref值
      }


      return (
      <button onClick={handleClick}>
      点击我！
      </button>
      );
      }
      • 这里的ref指向一个数字，
  • 但是像state一样，可以让他指向任何东西，字符串、对象、函数等。与state不同的是，ref是一个普通的对象，有一个可被读取、修改的current属性
  • 组件不会再每次递增时重新渲染，与state一样，React会在每次重新渲染之后保留ref。但是设置state会重新渲染组件，修改ref不会

大实例：使用ref制作秒表

  • 可以在单个组件中把ref和state结合起来使用。
    • 例如：制作秒表，用户可以通过按钮来控制启动、停止。为了显示用户按下的时间以来经过的时间长度。需要追踪按下开始按钮的时间和当前时间。此信息用于渲染，所以把它保存在state中
      const [startTime, setStartTime] = useState(null);
      const [now, setNow] = useState(null);
    • 用户摁下开始，将用setInterval每10毫秒更新一次时间
      import { useState } from 'react';

      export default function Stopwatch() {

      const [startTime, setStartTime] = useState(null);
      const [now, setNow] = useState(null);


      function handleStart() {
      // 开始计时。

      setStartTime(Date.now());
      setNow(Date.now());


      setInterval(() => {
      // 每 10ms 更新一次当前时间。

      setNow(Date.now());
      }, 10);
      }
      显示度过多少毫秒
      let secondsPassed = 0;
      if (startTime != null && now != null) {
      secondsPassed = (now - startTime) / 1000;
      }

      return (
      <>
      <h1>时间过去了： {secondsPassed.toFixed(3)}</h1>
      <button onClick={handleStart}>
      开始
      </button>
      </>
      );
      }
    • 当按下停止按钮时，需要取消现有的interval，来停止更新now state。可以通过调用clearInterval来完成此操作，但是需要为其提供intervalID，此ID是之前用户按下Start、调用setInterval时返回的，需要将ID保留在某处。
    • 由于intervalID不需要渲染，可以将其保存在ref中
      import { useState, useRef } from 'react';

      export default function Stopwatch() {

      const [startTime, setStartTime] = useState(null);
      const [now, setNow] = useState(null);
      const intervalRef = useRef(null);


      定义开始函数，开始时间和现在时间，清除ref现有值，设置现有值为新的now
      function handleStart() {

      setStartTime(Date.now());
      setNow(Date.now());
      确保
      清除上一轮开始设置的旧的ref值

      clearInterval(intervalRef.current);
      intervalRef.current = setInterval(() => {
      setNow(Date.now());
      }, 10);

      }

      定义结束函数，清除ref现有值
      function handleStop() {

      清除开始时设置的ref值

      clearInterval(intervalRef.current);
      }

      时间差

      let secondsPassed = 0;
      if (startTime != null && now != null) {
      secondsPassed = (now - startTime) / 1000;
      }


      return (
      <>
      <h1>时间过去了： {secondsPassed.toFixed(3)}</h1>
      <button onClick={handleStart}>
      开始
      </button>
      <button onClick={handleStop}>
      停止
      </button>
      </>
      );
      }
  • 当一条信息用于渲染，将他保存在state中，当一条信息仅被事件处理器需要，而且更改它不需要重新渲染时，使用ref会更有效

ref与state的不同：

  • 多数情况下建议使用state，ref仅是一种脱围机制。
    refstate
    useRef（initialValue）返回{current：initialValue}useState（initialValue）返回state变量的当前值和一个state设置函数（【value，setValue】）
    更改时不会触发重渲染更改时触发重渲染
    可变—在渲染过程之外可以修改和更新current的值不可变—必须使用setState设置函数来修改state变量，从而排队重新渲染
    不应该在渲染期间读取或更改current值可以随时读取state，但是每次渲染都有state快照
    • 实例，使用state实现的计数器
      import { useState } from 'react';

      export default function Counter() {

      const [count, setCount] = useState(0);


      function handleClick() {
      setCount(count + 1);
      }


      return (
      <button onClick={handleClick}>
      你点击了 {count} 次
      </button>
      );
      }
      • 使用setCount（）设置state值，React会重渲染组件，而且屏幕更新显示新的state
    • 实例，使用ref实现相同组件
      import { useRef } from 'react';

      export default function Counter() {
      let countRef = useRef(0);

      function handleClick() {
      // 这样并未重新渲染组件！
      countRef.current = countRef.current + 1;
      }

      return (
      <button onClick={handleClick}>
      你点击了 {countRef.current} 次
      </button>
      );
      }
      • React不会重新渲染组件，计数器不会发生变化，但是实际上的ref.current值被改变了

useRef内部的运行步骤：

  • 尽管useState和useRef都是React提供的Hook，原则上useRef可以在useState的基础上实现。
    • 在React内部，useRef时这样实现
      // React 内部
      function useRef(initialValue) {
      const [ref, unused] = useState({ current: initialValue });
      return ref;
      }
      • 在第一次渲染时，useRef返回{current：initialValue}，该对象由React存储，因此在下一次渲染期间将返回相同的对象。
        • 在这个示例中，setState设置函数没有被使用，而且他是不必要的，因为useRef总是返回相同对象
  • React提供了一个内置版本的useRef，因为他在实践中很常见，但是你可以将其视为没有设置函数的state变量，在面向对象编程中，ref类似于实例字段this.something。但实际结果是somethingRef.current。

何时使用ref：

  • 通常，当你的组件需要跳出React并与外部API通信时，会用到ref，通常不会影响组件外观的浏览器API，下面是常见实例
    • 存储timeout ID
    • 存储和操作DOM元素
    • 存储不需要被用来计算JSX的其他对象。
  • 总结就是，组件需要存储的值，但不影响渲染逻辑，就使用ref存储

ref的实践：

  • 遵守以下ref使用原则，会使组件更具可预测性
    • 将ref视为脱围机制
    • 不要再渲染过程中读取或写入ref.current
  • React state的限制不适用于ref，例如state的快照性质，不会同步更新等。但是更改ref的current值，会立即改变
  • 因为ref本身是普通的JS对象。使用ref时不需要担心避免变更，只要改变的对象不用于渲染，React就不会影响

ref和DOM：

  • 可以将ref指向任何值，最常见的ref用法是访问DOM元素，例如你想以编程方式聚焦一个输入框，使用ref。
    • 将ref传递给JSX中的ref属性时，比如<div ref={myRef}>，React会将响应的DOM元素放入myRef.current中，
    • 当元素从DOM中删除时，React会将myRef.current更新为null。

使用ref操作DOM

由于React会自动处理更新DOM一匹配你的渲染输出，因此组件中通常不需要操作DOM。但是有时需要访问由React管理的DOM元素，例如让一个节点来获得焦点，滚动到它或测量它的尺寸和位置。

在React中没有内置的方法来做这些事情，所以需要指向DOM节点的ref来实现。

获取指向节点的ref

  • 要访问由React管理的DOM节点，首先引入useRef Hook：
    • import {useRef} from ‘react’；
  • 然后，在你的组件中使用它声明一个ref
    • const myRef = useRef（null）
  • 最后将ref作为ref属性值传递给想要获取的DOM节点的JSX标签
    • <div ref={myRef}>
  • useRef Hook返回一个对象，该对象有一个名为current的属性，最初，myRef.current是null，当React为这个div创建一个DOM节点时，React会把对该节点的引用放入myRef.current。然后从事件处理器访问此DOM节点，并使用在上定义的内置浏览器API
    • myRef.current.scrollIntoView（）

示例：使文本输入框获得焦点：

  • 在本例中，单击按钮使输入框获得焦点
    import { useRef } from 'react';

    export default function Form() {

    const inputRef = useRef(null);


    function handleClick() {
    inputRef.current.focus();
    }


    return (
    <>

    <input ref={inputRef} /> 调用后会将该DOM节点赋值给ref
    <button onClick={handleClick}>
    聚焦输入框
    </button>
    </>
    );
    }
    • 实现这一点的流程如下
      • 使用useRef Hook声明inputRef
      • 像<input ref={inputRef}>这样使用ref，就告诉React将这个input的DOM节点放入inputRef.current
      • 在handleClick函数中，从inputRef.current读取input DOM节点并使用inputRef.current.focus（）调用他的focus（）
      • 使用onClick将handleClick事件处理器传递给button
  • 虽然DOM操作是ref最常见的例子，但是useRef Hook可用于存储React之外的其他容器中，例如计时器ID。
  • 与state类似，ref能在渲染之间保留。甚至可以将ref视为设置它们时不会触发重渲染的state变量。

使用ref回调管理ref列表：

  • 上面的例子中，ref的数量是预先确定的，但有时候，你可能需要为列表中每一项都绑定ref，但是又不知道会有多少项，使用列表循环是行不通的
    <ul>
    {items.map((item) => {
    // 行不通！
    const ref = useRef(null);
    return <li ref={ref} />;
    })}
    </ul>
    • 因为Hook只能在组件顶层被调用，不能再循环语句、条件语句、map（）函数中调用useRef
  • 一种可能的解决方案是用一个ref引用父元素，然后使用DOM操作方法，如querySelectorAll来寻找它的子节点，然而这种方法很脆弱，如果DOM结构发生改变，可能会失效或报错
  • 另一种方法是，将函数传递给ref属性，这称为ref回调，当需要设置ref时，React将传入DOM节点来调用ref回调，并在需要清除它时传入null。这可以维护自己的数组或map，并通过索引或某种类型的ID访问任何ref
    • 示例：展示如何使用上述方法滚动到长列表中的任意节点。
      import { useRef, useState } from "react";

      export default function CatFriends() {

      const itemsRef = useRef(null);
      const [catList, setCatList] = useState(setupCatList);


      function scrollToCat(cat) {

      const map = getMap();
      const node = map.get(cat);

      node.scrollIntoView({
      behavior: "smooth",
      block: "nearest",
      inline: "center",
      });
      }

      function getMap() {

      if (!itemsRef.current) {
      // 首次运行时初始化 Map。
      itemsRef.current = new Map();
      }
      return itemsRef.current;

      }

      return (
      <>
      <nav>

      <button onClick={() => scrollToCat(catList[0])}>Neo</button>
      <button onClick={() => scrollToCat(catList[5])}>Millie</button>
      <button onClick={() => scrollToCat(catList[9])}>Bella</button>
      </nav>
      <div>
      <ul>
      {catList.map((cat) => (
      <li
      key={cat}

      ref={(node) => {
      const map = getMap();
      map.set(cat, node);


      return () => {
      map.delete(cat);
      };
      }}
      >
      <img src={cat} />
      </li>
      ))}
      </ul>
      </div>
      </>
      );
      }


      function setupCatList() {
      const catList = [];
      for (let i = 0; i < 10; i++) {
      catList.push("https://loremflickr.com/320/240/cat?lock=" + i);
      }

      return catList;
      }

      • 在这个例子中，itemsRef保存的不是单个DOM节点，而是保存了包含列表项ID和DOM节点的Map（Ref可以保存任何值），每个列表项上的ref回调负责更新Map
        <li
        key={cat.id}
        ref={node => {
        const map = getMap();
        // 添加到 Map 中
        map.set(cat, node);

        return () => {
        // 从 Map 中移除
        map.delete(cat);
        };
        }}
        >
        • 这样之后就可以从Map中读取单个DOM节点

访问另一个组件的DOM节点：

  • 注意：Ref是一种脱围机制，手动操作其他组件的DOM节点会使代码变得脆弱
  • 可以像其他prop一样将ref从父组件传递给子组件
    import { useRef } from 'react';


    function MyInput({ ref }) {
    return <input ref={ref} />; 这是JSX
    }


    function MyForm() {
    const inputRef = useRef(null);

    return <MyInput ref={inputRef} /> 这是调用MyInput组件传递prop
    }
    • 此处，父组件创建了一个MyFrom的ref，并将它传递给了MyInput子组件，然后MyInput再将这个ref传递给<input>。
    • 因为<input>是一个内置组件，React会将ref的.current属性设置为这个input>DOM元素
  • 再MyFrom中创建的inputRef现在指向MyInput返回的<input>DOM元素，再MyFrom中创建的点击处理程序可以访问inputRef并且调用focus（）来将焦点设置在<input>上。
    import { useRef } from 'react';



    function MyInput({ ref }) {
    return <input ref={ref} />;
    }


    export default function MyForm() {

    const inputRef = useRef(null);



    function handleClick() {
    inputRef.current.focus();
    }


    return (
    <>

    <MyInput ref={inputRef} />
    <button onClick={handleClick}>
    聚焦输入框
    </button>
    </>
    );
    }

使用命令句柄暴露一部分API

  • 上面例子中，MyInput暴露了原始的DOM元素input，这让父元素可以对其调用focus（），然而，这也让父组件能够做其他事情，例如，改变其CSS样式。再不常见情况下，希望限制暴露的功能，可以使用useImperativeHandle来实现
    import { useRef, useImperativeHandle } from "react";


    function MyInput({ ref }) {

    const realInputRef = useRef(null);
    useImperativeHandle(ref, () => ({
    // 只暴露 focus，没有别的
    focus() {
    realInputRef.current.focus();
    },

    }));

    return <input ref={realInputRef} />;
    };


    export default function Form() {

    const inputRef = useRef(null);

    function handleClick() {
    inputRef.current.focus();
    }

    return (
    <>
    <MyInput ref={inputRef} />
    <button onClick={handleClick}>聚焦输入框</button>
    </>
    );
    }
  • 这里的MyInput中的realInputRef保存了实际的inputDOM节点，但是，useImperativeHandle知识React将你自己指定的对象作为父组件的ref值。
  • 所以From组件内的inputRef.current将只有focus方法，在这种情况下，ref句柄不是DOM节点，而是在useImperativeHanle调用中创建的自定义对象。

React何时添加refs：

  • 在React中，每次更新都分为两个阶段
    • 在渲染阶段：React调用组件来确定屏幕上应该显示什么
    • 再提交阶段：React把变更应用于DOM节点上
  • 通常不希望在渲染期间访问refs，这也适用于保存DOM节点的refs，在第一次渲染期间，DOM节点尚未创建，因此，ref.current值为null，在渲染更新的过程中，DOM节点还没有更新，所以读取refs还早
  • React在提交阶段设置ref.current，在更新DOM之前，React将受影响的ref.current的值设置为null，更新DOM之后，React将他们设置到对应的DOM节点
  • 通常，从事件处理器访问refs，如果你想使用ref执行某些操作，但没有特定的事件可以操作，就需要使用effect

使用refs操作DOM的实践

  • refs是一种脱围机制，只在必须跳出React时使用它们，常见实例包括管理焦点、滚动位置、调用React未暴露的浏览器API
  • 如果坚持聚焦和滚动等非破坏性操作，不会遇到问题，但是如果手动修改DOM，就会与React的更改发生冲突。
    • 例子：一条欢迎消息和两个按钮，第一个按钮使用条件渲染和state切换他的显示和隐藏，就像在React中常做的。第二个按钮使用remove（）DOM API将其从React控制之外的DOM中移除
      import { useState, useRef } from 'react';


      export default function Counter() {

      const [show, setShow] = useState(true);
      const ref = useRef(null);


      return (
      <div>
      <button

      onClick={() => {
      setShow(!show);
      }}>
      通过 setState 切换

      </button>
      <button

      onClick={() => {
      ref.current.remove();
      }}>
      从 DOM 中删除

      </button>
      {show && <p ref={ref}>Hello world</p>}
      </div>
      );
      }
      • 再手动删除DOM元素之后，尝试使用setState，在显示会报错，因为更改了DOM，React不知道如何管理
  • 避免更改由React管理的DOM节点，对于React管理的元素进行修改、添加子元素、删除子元素，会导致不一致的视觉结果，或与上述类似的崩溃
  • 但是不意味着，完全不能这样做，可以安全的谨慎的修改React没有理由更新的部分DOM。例如，某些div在JSX中为空，React没有理由去变动其子列表，因此在这里手动增删元素是可以的

使用Effect进行同步：

有些组件需要与外部系统同步，例如你希望根据React state控制非React组件、建立服务器链接或当组件在页面显示时发送分析日志。

Effect允许你在渲染结束后执行一些代码，一边将组件与React外部的某个系统

同步

什么是Effect，与事件Event的区别：

  • 在接触Effect之前，需要熟悉React组件中的两种逻辑类型
    • 渲染代码：位于组件的顶层，你在这里处理props和state，对他们进行转换，并返回希望在页面上显示的JSX。渲染代码必须是纯函数，只根据输入内容，计算输出内容，不进行其他处理
    • 事件处理程序：是组件内部的嵌套函数，他们不光进行计算，还会执行操作。事件处理程序可能会更新输入字段，提交HTTP POST请求，或将用户导航到另一个页面，事件处理程序包含由特定用户操作（例如按钮点击或输入）引起的副作用（改变程序的状态）
  • 有时候会使用其他组件，ChatRoom组件，在页面上显示时必须连接到聊天服务器，连接到服务器并不是纯函数（是一个副作用），因此他不能再渲染期间发生，然而，并没有特定的事件（比如点击）能让ChatRoom被显示
  • Effect允许你指定由渲染自身，而不是特定事件引起的副作用
  • 就比如在聊天中发送消息是一个事件，因为他直接由用户点击特定按钮引起。然而建立服务器连接是一个Effect，因为无论哪种交互导致组件出现，他都应该发上升，Effect再提交结束后，页面更新后运行。此时是将React组件与外部系统（如网络或第三方库）同步的最佳时机

可能不需要Effect：

  • 不要急于在组件中使用Effect。
  • Effect通常用于暂时跳出React并于一些外部系统进行同步。包括浏览器API、第三方小组件、以及网络等等。
  • 如果Effect只是根据其他状态来调整状态，那么可能不需要使用Effect

如何编写Effect：

  • 要编写一个Effect，遵循以下三个步骤
    • 声明Effect：通常Effect会在每次提交后运行。
    • 指定Effect依赖：大多数Effect应该按需运行，而不是在每次渲染后都运行，例如，但如动画应该只在组件出现时触发，连接与断开服务器的操作只应在组件中出现消失时，或者切换聊天室时执行。需要通过指定依赖项来学习如何控制这一点。
    • 必要时添加清理操作：一些Effect需要制定如何停止、撤销，或清除他们所执行的操作，例如“连接”需要“断开”，“订阅”需要“退订”，”获取数据“需要“取消”或”忽略“

第一步：声明Effect：

  • 从React中导入useEffect Hook
    • import {useEffect} from ‘react’；
  • 在组件顶部调用，并加入一些代码
    function MyComponent() {
    useEffect(() => {
    // 每次渲染后都会执行此处的代码
    });
    return <div />;
    }
  • 每当组件渲染时，React会先更新页面，然后再运行useEffect中的代码，换句话说，useEffect会延迟一段代码的运行，知道渲染结果反映在页面上。
  • 接下来，演示如何使用Effect与外部系统同步，考虑一个<VideoPlayer>React组件，通关传递一个isPlaying prop来控制它不妨或暂停音频
    • <VideoPlayer isPlaying={isPlaying} />
  • 这个VideoPlayer组件渲染了浏览器内置的video>标签
    function VideoPlayer({ src, isPlaying }) {
    // TODO：使用 isPlaying 做一些事情
    return <video src={src} />;
    }
  • 但是浏览器中video>标签没有isPlaying属性，控制它的唯一方式是在DOM元素中调用play（）和pause（）方法，因此，需要将isPlaying prop的值（表示是否应该播放）与play（）和pause（）等函数的调用进行同步。
    • 首先要获取video>DOM节点的对象引用
    • 然后尝试在渲染期间调用play（）或pause（）
      import { useState, useRef, useEffect } from 'react';

      function VideoPlayer({ src, isPlaying }) {
      const ref = useRef(null);

      if (isPlaying) {
      ref.current.play(); // 渲染期间不能调用 `play()`。
      } else {
      ref.current.pause(); // 同样，调用 `pause()` 也不行。
      }

      return <video ref={ref} src={src} loop playsInline />;
      }

      export default function App() {
      const [isPlaying, setIsPlaying] = useState(false);
      return (
      <>
      <button onClick={() => setIsPlaying(!isPlaying)}>
      {isPlaying ? '暂停' : '播放'}
      </button>
      <VideoPlayer
      isPlaying={isPlaying}
      src="https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4"
      />
      </>
      );
      }
    • 这段代码会报错，因为他在渲染期间对DOM节点进行操作。在React中，渲染应该是纯粹的计算JSX，不应该包含任何像修改DOM的副作用
    • 而且第一次调用VideoPlayer组件时，对应的DOM节点还不存在，因为React在返回JSX之前不知道要创建什么样的DOM，所以没有DOM节点可以调用play（）或pause（）方法。
      • 解决办法是使用useEffect包裹副作用，把他分离到渲染逻辑的计算过程之外
        import { useEffect, useRef } from 'react';

        function VideoPlayer({ src, isPlaying }) {
        const ref = useRef(null);


        useEffect(() => {
        if (isPlaying) {
        ref.current.play();
        } else {
        ref.current.pause();
        }
        });


        return <video ref={ref} src={src} loop playsInline />;
        }
      • 将DOM更新封装在Effect中，可以让React先更新页面，在运行Effect。
      • 当VideoPlayer组件渲染时，无论是否为首次渲染，都会发生以下步骤：首先React会更新页面，确保video标签带着正确的props出现在DOM中，之后React将运行Effect，最后Effect根据isPlaying的值调用play（）或pause（）
  • 在上述示例中，同步到React state的外部系统时浏览器媒体API，也可以使用类似的方法将传统的非React代码（如jQuery插件）封装成声明式的React组件
  • 要注意的是，控制视频播放器在实际应用中复杂很多：比如调用play（）会失败，用户可能会使用内置的浏览器控件来进行播放或暂停操作。

第二部：指定Effect的依赖项：

  • 默认情况下，Effect会在每次选然后运行，这有时是不想要的
    • 有时，他会运行很慢，与外部系统的同步不是即时的，所以可能希望在不必要时跳过他，例如不想在每次打字时都会重新连接聊天服务器
    • 有时，他会报错，例如，不想再每次按键时都出发组件的但如动画，动画应该只在组件首次出现时播放。
  • 示例：在之前例子中加入console.log调用和一个更新父组件state的文本输入框。注意在输入时是如何触发Effect重新运行的
    import { useState, useRef, useEffect } from 'react';

    const ref = useRef(null);

    useEffect(() => {
    if (isPlaying) {
    console.log('调用 video.play()');
    ref.current.play();
    } else {
    console.log('调用 video.pause()');

    }

    return <video ref={ref} src={src} loop playsInline />;

    export default function App() {

    return (
    <>

    • 通过在调用useEffect时指定一个依赖数组作为第二个参数，可以让React跳过不必要的重新运行Effect。
      • 在上述示例中，传入一个空数组
        useEffect(() => {
        // ...
        }, []);
      • 会出现错误提示
        • React Hook useEffect has a missing dependency: 'isPlaying'：
    • 原因在于，Effect内部代码依赖于isPlayingprop决定做什么，但是没有显式声明这个依赖关系。
      • 将isPlaying添加到依赖数组中
        useEffect(() => {
        if (isPlaying) { // isPlaying 在此处使用……
        // ...
        } else {
        // ...
        }
        }, [isPlaying]); // ……所以它必须在此处声明！

      现在所有依赖都已经声明，指定isPlaying作为依赖数组，会告诉React：如果isPlaying与上次渲染时相同，就跳过重新运行Effect，这样，输入框的输入不会触发Effect的重新运行，只有按下播放/暂停按钮会触发。

  • 示例完整代码

  • 依赖数组可以包含多个依赖项，只有所有指定的依赖项的值都与上次渲染时完全相同，React才会跳过运行Effect更新。
  • 请注意：不可以随便使用”选择“依赖项，如果指定的依赖项与React根据Effect内部代码所推断出的依赖项不匹配，会受到错误提示。这有助于捕捉代码中的bug
  • 如果不希望某些代码重新运行，应该修改Effect代码本身，使其不需要使用依赖项

依赖数组可以省略ref：

  • 下面的Effect同时使用了ref与isPlaying prop但是只有isPlaying被声明为依赖项
    function VideoPlayer({ src, isPlaying }) {
    const ref = useRef(null);
    useEffect(() => {
    if (isPlaying) {
    ref.current.play();
    } else {
    ref.current.pause();
    }
    }, [isPlaying]);
  • 因为ref具有稳定地标识，React确保你在每轮渲染中调用的同一个useRef时，总能获得相同的对象，ref不会改变，所以他不会导致重新运行Effect，所以，在依赖数组中它可有可无
  • useState返回的set函数也具有稳定地标识，因此它们通常被忽略，如果在省略某个依赖项时linter不会报错，那么这样做就是安全的
  • 省略始终稳定的依赖项，仅能在linter能看到对象是稳定的时候才有效。例如，如果ref时父组件传递过来的，就必须在依赖数组中指定他，很有必要，因为无法确定父组件一直传递相同的ref，还是根据条件传递不同的ref。所以，Effect会依赖于被传递的是哪个ref

第三步：按需添加清理（cleanup）函数：

  • 考虑一个不同的例子。加入正在编写一个ChatRoom组件，该组件在显示时需要连接到聊天服务器，现在为你提供了createConnection（）的API，该API返回一个包含connect（）与disconnection（）方法的对象。
    • 如何确保组件在显示时始终保持连接？
      • 首先，编写Effect的逻辑
        useEffect(() => {
        const connection = createConnection();
        connection.connect();
        });
      • 如果每次重新渲染后都得重新连接，会很慢，需要添加依赖数组
        useEffect(() => {
        const connection = createConnection();
        connection.connect();
        }, []);
      • 由于Effect中的代码没有使用props或state，所以依赖数组为空数组，尽在组件首次挂载时运行Effect
        • chat.js
          export function createConnection() {
          // 真正的实现实际上会连接到服务器
          return {
          connect() {
          console.log('✅ 连接中……');
          },
          disconnect() {
          console.log('❌ 连接断开。');
          }
          };
          }
        • App.js
          import { useEffect } from 'react';
          import { createConnection } from './chat.js';

          export default function ChatRoom() {
          useEffect(() => {
          const connection = createConnection();
          connection.connect();
          }, []);
          return <h1>欢迎来到聊天室！</h1>;
          }
      • 这里的Effect仅在组件挂载时运行，但实际上”连接中“被打印了两次
        • 假设ChatRoom组件是一个大型多页面应用中的一部分，用户最初再ChatRoom页面，组件挂载并调用connection.connect（），接着用户可能会导航到另一个页面，比如切换到设置页面，于是ChatRoom组件被卸载。最后，用户点击返回时，ChatRoom组件再次挂载，这将建立第二个连接—但第一个链接未被销毁，随着用户在应用中来回切换，这连接将不断累积。
        • 这类bug在没有大量手动测试的情况下很容易被忽略，在开发环境中，React会在组件首次挂载后立即重新挂载一次。
      • 两次出现“连接中”，出现问题：在代码中，组件被卸载时没有关闭连接。
    • 为解决这个问题，可以在Effect中返回一个清理（cleanup）函数。
      useEffect(() => {
      const connection = createConnection();
      connection.connect();
      return () => {
      connection.disconnect();
      };
      }, []);
  • React会在每次Effect重新运行之前调用清理函数，并在组件卸载之后，在调用一次清理函数
    • 示例，清理函数步骤
      • chat.js
        export function createConnection() {
        // 真正的实现实际上会连接到服务器
        return {
        connect() {
        console.log('✅ 连接中……');
        },
        disconnect() {
        console.log('❌ 连接断开。');
        }
        };
        }
      • App.js
        import { useState, useEffect } from 'react';
        import { createConnection } from './chat.js';

        export default function ChatRoom() {
        useEffect(() => {
        const connection = createConnection();
        connection.connect();

        return () => connection.disconnect();
        }, []);
        return <h1>欢迎来到聊天室！</h1>;
        }
  • 在开发环境中，通过重新挂载你的组件，React验证了离开页面在返回后不会导致代码出错。因为本就应该先断开再重新连接。无论是只执行一次Effect，还是执行、清理、在执行，都应该没有用户可见的区别，之所以会有额外的一次connect/disconnect调用，是因为再开发环境下React检测代码中的bug，这是正常现象。
  • 在生产环境下，只会看到“连接中”打印一次。这是因为重新挂载组件只会在开发环境下运行，来帮助找到需要清理的Effect，

如何处理再开发环境下Effect运行了两次：

  • React有意在开发环境下重新挂载你的组件，来找到类似上例中的bug，需要思考的不是“如何只运行一次Effect”，而是“如何修复Effect来让他在重新挂载后正常运行。”
    • 通常是使用清理函数，清理函数应该停止或撤销Effect所做的一切，原则是用户不应该感受到Effect只执行了一次（再生产环境中）和连续执行“挂载-清理-挂载”（开发环境中）之间的区别。
  • 编写的Effect应该符合下列常见模式之一
    • 管理非React小部件
    • 订阅事件
    • 触发动画
    • 获取数据
    • 发送分析报告
  • 不使用Effect的的模式
    • 初始化应用
    • 购买商品

【解释上述模式】

  • 管理非React小部件 ：
    • 有时需要添加不是使用React实现的UI部件，比如在页面中添加一个地图组件，有一个setZoomLevel（）方法，然后希望地图的缩放比例和代码中的zoomLevel state保持同步，你的Effect类似于
      useEffect(() => {
      const map = mapRef.current;
      map.setZoomLevel(zoomLevel);
      }, [zoomLevel]);
      • 这种情况下，不需要清理操作，在开发环境中，R二act会调用Effect两次，但是没关系，使用相同的值调用setZoomLevel两次不会造成任何影响，虽然在开发环境下可能会稍微慢一些，但是问题不大，生产环境下他不会多余的重新挂载
    • 有些API可能不允许连续调用两次，例如内置的<dialog>元素的showModal方法，在连续被调用两次时会爆出一场，此时就可以通过实现清理函数来使其关闭对话框
      useEffect(() => {
      const dialog = dialogRef.current;
      dialog.showModal();
      return () => dialog.close();
      }, []);
      • 开发环境中，Effect会先调用showModal（）然后立即调用close（），之后再次调用showModal（），这与再生产环境中只调用一次showModal（）的用户可见行为是相同的
  • 订阅事件：
    • 如果Effect订阅了某些事件，清理函数应该退订这些事件
      useEffect(() => {
      function handleScroll(e) {
      console.log(window.scrollX, window.scrollY);
      }
      window.addEventListener('scroll', handleScroll);
      return () => window.removeEventListener('scroll', handleScroll);
      }, []);
      • 在开发环境中，你的Effect湖西岸调用addEventListener（），然后立即调用removeEventListener（），接着再次使用享用的处理函数调用addEventListener（），因此每次只会有一个有效订阅，这与再生产环境中只调用一次addEventListener（）所产生的用户可见行为是相同的
  • 触发动画：
    • 如果Effect触发了一些动画，清理函数应该将动画重置为初始状态
      useEffect(() => {
      const node = ref.current;
      node.style.opacity = 1; // 触发动画
      return () => {
      node.style.opacity = 0; // 重置为初始值
      };
      }, []);
      • 开发环境中，透明度由1到0再变为1，这与再生产环境中，直接将其设置为1具有相同的用户可见行为。如果你使用了支持补间动画的第三方动画库，你的清理函数应该将时间轴重置为初始状态。
  • 获取数据：
    • 如果Effect需要获取数据，清理函数硬终止请求或忽略其结果
      useEffect(() => {
      let ignore = false;

      async function startFetching() {
      const json = await fetchTodos(userId);
      if (!ignore) {
      setTodos(json);
      }
      }

      startFetching();

      return () => {
      ignore = true;
      };
      }, [userId]);
      • 无法撤销已经发生的网络请求，但是清理函数应到确保哪些不在相关的请求不会继续影响你的应用。例如userId从alice变为bob，确保alice的响应数据被忽略，即使他在bob之后到达
    • 开发环境中，会在浏览器调试工具中的网络选项卡看到两条请求，使用上述方法，第一个Effect立即被清理，所以他的ignore变量会被设置为true，因此即使有额外的请求，由于if（！ignore）的检查，也不会影响state。
    • 生产环境中，只有一条请求，如果开发环境中的第二次请求造成了困扰，最好的办法是使用一个能够对请求去重并缓存响应的方案
      function TodoList() {
      const todos = useSomeDataLibrary(`/api/user/${userId}/todos`);
      // .
      • 这样可以提高开发体验，还可以是你的应用响应更快，例如用户点击返回按钮时，不用再等待数据重新加载，因为以及缓存好了，可以构建这样的缓存机制，也可以使用很多再Effect中手动获取数据的替代方法。
  • 发送分析报告：
    • 下面代码，再页面访问时发送一个分析事件
      useEffect(() => {
      logVisit(url); // 发送 POST 请求
      }, [url]);
      • 开发环境中，对于每个URL，logVisit会被调用两次，因此你可能会尝试修复，这个东西建议保持不变，与之前示例类似，运行一次还是两次，在用户可见行为上没有区别，从实际角度来看，logVisit不应该在开发环境中执行任何操作，因为不想让开发设备的日志影响生产环境的统计数据。每次保存文件时组件都会重新挂载，因此再开发环境中会记录额外的访问日志。
      • 在生产环境中，不会有重复的访问日志
      • 为了调试发送的分析事件，你可以将应用部署到一个运行在生产模式下的暂存环境，或者暂时禁用 严格模式 及其仅在开发环境中的重新挂载检查。你还可以在路由更改的事件处理程序中发送分析数据，而不是在 Effect 中发送。对于更精确的分析，可以使用交叉观察器 来跟踪哪些组件位于视口中以及它们保持可见的时间。

【解释上述不适合模式】：

  • 初始化应用：
    • 某些逻辑应该只在应用启动时运行一次，可以将它放在组件外部
      if (typeof window !== 'undefined') { // 检查是否在浏览器中运行
      checkAuthToken();
      loadDataFromLocalStorage();
      }

      function App() {
      // ……
      }
      • 这可以确保此类逻辑只在浏览器加载页面后只运行1次
  • 购买商品：
    • 有时，即便编写了清理函数，也无法避免用户观察到Effect运行了两次，比如你的Effect发送了一个像购买商品这样的POST请求
      useEffect(() => {
      // 🔴 错误：此处的 Effect 在开发环境中会触发两次，暴露出代码中的问题。
      fetch('/api/buy', { method: 'POST' });
      }, []);
      • 这样会导致购买两次商品，这也是为什么不应该把这种逻辑放在Effect中，如果用户跳转到另一个页面，然后按下返回按钮，你的Effect会再次运行，用户每次访问页面时旧购买商品，这样是不对的，而是再他们点击购买按钮时才会购买
    • 购买操作不是渲染引起的，而是由特定的交互引起的，他应该只在用户按下按钮时执行，因此，他不应该写在Effect中，应当把/api/buy请求移动到购买按钮的事件处理程序中。
      function handleClick() {
      // ✅ 购买行为是一个事件，因为它是由特定的交互引起的。
      fetch('/api/buy', { method: 'POST' });
      }
      • 这说明了，如果重新挂载破坏了应用的逻辑，通常变暴露了存在的bug。对用户而言，访问同一个页面，不应该与访问页面后点击链接、再按下返回按钮查看页面有区别。
      • React通过再开发环境中重新挂载组件来验证你的组件是否遵守这一原则。

【综合上述模块】：

  • 实例，使用setTimeout调度一个日志记录，日志会在Effect运行三秒后显示输入的文本，清理函数会取消挂起的延时器。从按下挂载组件开始
    import { useState, useEffect } from 'react';

    function Playground() {
    const [text, setText] = useState('a');

    useEffect(() => {
    function onTimeout() {
    console.log('⏰ ' + text);
    }

    console.log('🔵 调度 "' + text + '" 日志');
    const timeoutId = setTimeout(onTimeout, 3000);

    return () => {
    console.log('🟡 取消 "' + text + '" 日志');
    clearTimeout(timeoutId);
    };
    }, [text]);

    return (
    <>
    <label>
    日志内容：{' '}
    <input
    value={text}
    onChange={e => setText(e.target.value)}
    />
    </label>
    <h1>{text}</h1>
    </>
    );
    }

    export default function App() {
    const [show, setShow] = useState(false);
    return (
    <>
    <button onClick={() => setShow(!show)}>
    {show ? '卸载' : '挂载'}组件
    </button>
    {show && <hr />}
    {show && <Playground />}
    </>
    );
    }
    • 首先看到三条日志：调度a日志，取消a日志，再调度a日志。三秒后会看到日志a。额外的调度、取消是因为React在开发环境中会重新挂载一次，来验证是否实现了清理操作
  • 编辑输入框，如果编辑输入足够快，会看到调度的日志。React总是在执行下一轮渲染之前的Effect之前清理上一轮渲染的Effect，这就是为什么即使快速输入，最多也只有一个延时器被调度。
  • 在输入框中输入一些内容，然后立即按下“卸载组件”。注意卸载组件时是如何清理最后一轮渲染的 Effect 的。在这里，它会在最后一个延迟器要触发之前取消它。
  • 最后，在上面的代码中注释掉清理函数，这样延时器就不会被取消。尝试快速输入 abcde。你觉得三秒后会发生什么？延时器中的 console.log(text) 会打印 最新 的 text 值并生成五条 abcde 日志吗？试试看吧，验证一下你的直觉！
  • 三秒后，你应该会看到一系列的日志：a、ab、abc、abcd 与 abcde，而不是五条 abcde 日志。这是因为 每个 Effect 都会“捕获”它对应渲染时的 text 值。即使 text 的值发生了变化，渲染时 text = 'ab' 的 Effect 总是会得到 'ab'。换句话说，每个渲染的 Effect 都是相互独立的。如果你对这种机制感兴趣，可以阅读有关 闭包 的内容

每一轮渲染都有自己的Effect：

  • 可以将useEffect理解为附加一段行为到渲染输出中。
    • 实例 Effect
      export default function ChatRoom({ roomId }) {
      useEffect(() => {
      const connection = createConnection(roomId);
      connection.connect();
      return () => connection.disconnect();
      }, [roomId]);

      return <h1>欢迎来到 {roomId}！</h1>;
      }
      • 应用程序切换页面时发生的步骤
        • 初次渲染
        • 依赖项相同时重新渲染
        • 依赖项不同时的重新渲染
        • 组件卸载
  • 初次渲染
    • 用户访问组件ChatRoom，假设roomId的值为general
      // 首次渲染时的 JSX（roomId 为 "general"）
      return <h1>欢迎。来到 general！</h1>;
      • Effect也是渲染输出的一部分。首次渲染的Effect变为
        //首先渲染时的 Effect（roomId 为 "general"）
        () => {
        const connection = createConnection('general');
        connection.connect();
        return () => connection.disconnect();
        },
        // 首次渲染时的依赖项（roomId 为 "general"）
        ['general']
        • React运行这个Effect来连接到general聊天室
  • 依赖项相同时的重新渲染
    • 假设组件ChatRoom重新渲染，输出的JSX不变
      // 第二次渲染时的 JSX（roomId 为 "general"）
      return <h1>Welcome to general!</h1>;
      • React看到渲染时输出的没有改变，所以不更新DOM
      • 第二次渲染的Effect如下所示
        // 第二次渲染时的 Effect（roomId 为 "general"）
        () => {
        const connection = createConnection('general');
        connection.connect();
        return () => connection.disconnect();
        },
        // 第二次渲染时的依赖项（roomId 为 "general"）
        ['general']
        • React将第二次渲染时的roomId与第一次渲染时的roomId进行比较。Effect不会被调用
    • 因为所有的依赖项都相同，React忽略第二次渲染时的Effect。
  • 依赖项不同时的重新渲染
    • 接着，用户访问量ChatRoom组件，这一次组件，返回了不同的JSX
      // 第三次渲染时的 JSX（roomId 为 "travel"）
      return <h1>欢迎来到 travel！</h1>;
      • React更新DOM，将general改为travel
      • 第三次渲染的Effect如下
        // 第三次渲染时的 Effect（roomId 为 "travel"）
        () => {
        const connection = createConnection('travel');
        connection.connect();
        return () => connection.disconnect();
        },
        // 第三次渲染时的依赖项（roomId 为 "travel"）
        ['travel']
        • React将第三次渲染时的roomId与第二次渲染的roomId相比，发现依赖项不同：Object.is（“travel”，“general”）为false，因此Effect不能被跳过
    • 在React执行第三次渲染的Effect之前，它需要清理上一个运行的Effect。
      • 第二次渲染的Effect被调过来，所以React需要清理第一次渲染是的Effect。如果会看第一次渲染，可以发现第一次渲染时的清理函数所做的事，是在createConnection（“general”）所创建的连接上调用disconnect（），也就是从general聊天室断开连接
        • 之后React执行第三次渲染的Effect，他连接到travel聊天室
  • 组件卸载：
    • 最后假设用户离开了当前页面，ChatRoom组件被卸载，React执行上一个运行的Effect的清理函数，也就是第三次渲染时的Effect。这个清理函数销毁travel创建的链接。
  • 仅开发环境下的行为：
    • 开启严格模式，React在每次挂载组件后都会重新挂载组件（组件的state与创建的DOM都会被保留）。它可以帮助你找出需要添加清理函数的Effect，并在早期暴露类似竟态条件这样的bug，此外，每当在开发哈环境中保存文件时，React也会重新挂载Effect。这些行为都仅限于开发环境。

可能不需要使用Effect：

Effect时React范式中的一种脱围机制，可以脱离React并使组件和外部的一些系统同步，比如非React组件、网络、浏览器DOM。如果没有涉及到外部系统（例如，像根据props或state的变化来更新一个组件的state），就不应该使用Effect。移除不必要的Effect可以使代码更容易理解，运行得更快

如何移除不必要的Effect：

  • 有两种不必使用Effect的常见情况。
    • 不必使用Effect来转换渲染所需的数据：
      • 例如想在展示一个列表前先做筛选。直觉告诉你可能写一个当列表变化时更新state变量的Effect。然而这是低效的。当更新state时，React会首先调用组件函数来计算，应该显示的内容，然后React会把这些变化提交到DOM来更新屏幕，然后React执行Effect，如果Effect也立即更新了state，就会重新执行这个流程，为了避免不必要的渲染流程，应该在组件顶层转换数据，这些大门会在props或state变化时自动重新执行。
    • 不必使用Effect来处理用户事件：
      • 例如，想在用户购买一个产品时发送一个/api/bug的POST请求并展示一个提示，在购买按钮的点击事件处理函数中，你想知道会发生什么，但是当一个Effect运行时，却不知道用户做了什么，比如点击了哪个按钮。这就是为什么通常在相应的事件处理函数中处理用户事件。
    • 可以使用Effect来和外部系统同步，
      • 例如可以写一个Effect来保持一个jQuery的组件和React state之间的同步，也可以使用Effect来获取数据：例如，你可以同步当前的查询搜索与查询结果，记住，比起直接在组件中写Effect，现代框架提供了更有效地，内置的数据获取机制。

以下是常见的实例：

【根据props或state来更新state】：

  • 假设有一个包含了两个state变量的组件：firstName和lastName。想通过他们联合计算出fullName，此外，每当first和last两个组件变化是，fullName都能更新，
    • 第一直觉是添加一个state变量，fullname，并在Effect中更新它
      function Form() {
      const [firstName, setFirstName] = useState('Taylor');
      const [lastName, setLastName] = useState('Swift');

      // 🔴 避免：多余的 state 和不必要的 Effect
      const [fullName, setFullName] = useState('');
      useEffect(() => {
      setFullName(firstName + ' ' + lastName);
      }, [firstName, lastName]);
      // ...
      }
      • 大可不必复杂，而且这样效率同样不高，现时使用fullName的旧值执行了渲染流程，之后立即使用更新后得知重新渲染一遍
    • 移除state变量和Effect
      function Form() {
      const [firstName, setFirstName] = useState('Taylor');
      const [lastName, setLastName] = useState('Swift');
      // ✅ 非常好：在渲染期间进行计算
      const fullName = firstName + ' ' + lastName;
      // ...
      }
  • 如果一个值可以基于现有的props或state计算的出来，不要把它作为一个state，而是在渲染期间直接计算这个值
    • 这会使代码更快，避免了多余的级联更新，更简洁，以及更少出错。

【缓存昂贵的计算】：

  • 这个组件使用它接收到的props中的filter对另一个prop todos进行筛选，计算得出visibleTodos
    • 直觉可能是将结果存放到state中，在使用Effect更新他
      function TodoList({ todos, filter }) {
      const [newTodo, setNewTodo] = useState('');

      // 🔴 避免：多余的 state 和不必要的 Effect
      const [visibleTodos, setVisibleTodos] = useState([]);
      useEffect(() => {
      setVisibleTodos(getFilteredTodos(todos, filter));
      }, [todos, filter]);

      // ...
      }
      • 就像之前的例子一样，没有必要，也很低效
    • 首先移除state和Effect
      function TodoList({ todos, filter }) {
      const [newTodo, setNewTodo] = useState('');
      // ✅ 如果 getFilteredTodos() 的耗时不长，这样写就可以了。
      const visibleTodos = getFilteredTodos(todos, filter);
      // ...
      }
      • 因为getFilteredTodos（）可能会耗时很长，或者有很多todos，这些情况下，newTodo这样不相关的state变量发生变化时，不想要重新执行getFilterTodos（）
    • 可以使用useMemo Hook缓存，或者说记忆（memoize），这个复杂的计算
      import { useMemo, useState } from 'react';

      function TodoList({ todos, filter }) {
      const [newTodo, setNewTodo] = useState('');

      const visibleTodos = useMemo(() => {
      // ✅ 除非 todos 或 filter 发生变化，否则不会重新执行
      return getFilteredTodos(todos, filter);
      }, [todos, filter]);
      // ...
      或者写成
      const visibleTodos = useMemo(() => getFilteredTodos(todos, filter), [todos, filter]);

      }
  • 这回告诉React，除非todos或filter发生变化，否则不要重新执行传入的函数。
    • React会在初次渲染时记住getFilteredTodos（）的返回值，在下次渲染时，如果没有发生变化，就会使用保存的结果，不一样，再调用函数，并保存结果
  • 传入的useMemo的函数会在渲染期间执行，所以只适用于纯函数场景

如何判断计算是复杂昂贵的：

  • 一般来说只有创建或循环了成千上万对象时才会耗费时间，
    • 可以在控制台输出来测量某一段代码的执行时间，来确认
      console.time('筛选数组');
      const visibleTodos = getFilteredTodos(todos, filter);
      console.timeEnd('筛选数组');
    • 触发要测量的交互，例如在输入框中输入，会在控制台看到类似0.15ms的输出日志，如果总耗时达到了一定量及比如1ms或更多，那么计算结果记忆起来memoize是有意义的。
  • useMemo不会让第一次渲染变快，他只是帮助你跳过不必要的更新。
  • 如果你的设备性能比用户的更好，最好通过人工限制工具来测试性能，比如chrome的CPU节流工具。

【当props变化时重置所有state】：

  • 例如ProfilePage组件接收一个prop：userId。页面上有一个评论输入框，你用了一个state：comment来保存它的值，有一天发现，当你从一个人的个人资料导航到另一个时，comment没有被重置，就很容易把评论发送到不正确的个人哪里。
    • 正常来说，想在userId变化时，清除comment变量：
      export default function ProfilePage({ userId }) {
      const [comment, setComment] = useState('');

      // 🔴 避免：当 prop 变化时，在 Effect 中重置 state
      useEffect(() => {
      setComment('');
      }, [userId]);
      // ...
      }
      • 这是低效的，因为ProfilePage和它的子组件首先会使用旧值渲染，然后再用新值重新计算渲染，这样做很复杂，因为需要在ProfilePage里面所有具有state的组件中都写这样的代码。例如评论区的UI是嵌套的，你想清楚嵌套中的comment state
    • 取而代之的是，可以为每个用户的个人资料组件提供一个明确的键来告诉React他们原则上不同的个人资料组件，
    • 将组件拆分为两份，并从外部的组件传递key属性给内部的组件：
      export default function ProfilePage({ userId }) {
      return (
      <Profile
      userId={userId}
      key={userId}
      />
      );
      }

      function Profile({ userId }) {
      // ✅ 当 key 变化时，该组件内的 comment 或其他 state 会自动被重置
      const [comment, setComment] = useState('');
      // ...
      }
    • 通常，当在相同的位置渲染相同的组件时，React 会保留状态。通过将 userId 作为 key 传递给 Profile 组件，使 React 将具有不同 userId 的两个 Profile 组件视为两个不应共享任何状态的不同组件
    • 每当 key（这里是 userId）变化时，React 将重新创建 DOM，并 重置 Profile 组件和它的所有子组件的 state。现在，当在不同的个人资料之间导航时，comment 区域将自动被清空。
    • 请注意，在这个例子中，只有外部的 ProfilePage 组件被导出并在项目中对其他文件可见。渲染 ProfilePage 的那些组件不用传递 key 给它：它们只需把 userId 作为常规 prop 传入即可。而 ProfilePage 将其作为 key 传递给内部的 Profile 组件是它的实现细节而已。
